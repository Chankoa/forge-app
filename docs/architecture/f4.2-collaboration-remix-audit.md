# F4.2 Collaboration and Remix Audit

## Current capability model

The current course relationship model is intentionally role-independent: `courses.teacher_id` determines owner authoring capability and `enrollments` determines learning capability. An owner who is enrolled has both capabilities; no global `profiles.role` is used.

## Collaboration foundation

The deployed database already provides `public.course_memberships(course_id, user_id, role, status, invited_by, timestamps)` with unique `(course_id, user_id)`. Its roles are `viewer`, `participant`, `contributor`, `editor`, and `owner`; its statuses are `invited`, `active`, `suspended`, and `revoked`.

`courses.teacher_id` remains the canonical owner. An `owner` membership is not an independent ownership authority and cannot grant authoring, publication, archive, restore, deletion, or transfer authority. I.0.B reads only the authenticated user's membership under the existing self-read RLS policy and carries it through the shared capability resolver without granting new access.

Current authoring and source RLS still require `courses.teacher_id = auth.uid()` / `private.teacher_owns_course(...)`. Membership-based private reads, viewer/reviewer behavior, editor authoring, contributor scopes, storage access, invitations, and membership writes remain deferred until explicit RLS work. Do not add a parallel collaborator table.

## Archive and retention

The deployed `courses.status` already includes `archived`. I.0.B adds owner-only archive and restore transitions: archive sets `archived/private/preview` and clears `published_at`; restore returns to `draft/private/preview` and does not republish. Archived courses are excluded from Explorer, enrollment, learner access, and learner source access while the canonical owner retains authoring, Forge, source, resource, and restoration access.

Archive retains enrollments, progress, notes, resources, sources, and memberships. No course delete action is exposed. A pure preflight can only mark a draft candidate disposable when enrollments, progress, memberships, sources, resources, provenance, and every checked dependency are verified empty; unknown counts block. Sources are always a blocker because deleting a course nulls `course_sources.course_id` without transactional storage cleanup.

## Remix

No source-lineage column, clone action, transactional copy procedure or RLS policy exists for a derived course. A Remix action cannot safely clone course, module, lesson and source relationships while retaining an immutable source reference in the current schema.

Remix is deferred rather than presented as a dead control.

Minimal next-sprint proposal: create a new owner draft plus a lineage relation/fields such as `source_course_id` and remix metadata, then clone permitted course structure under the requesting session with explicit decisions for source reuse, enrollment independence, attribution and publication.

## Decision

F4 keeps the contextual multi-capability UX (`J'apprends · Je crée`) and does not add Learner/Teacher modes. I.0.B reuses deployed memberships and archive status without a migration. Collaborator permissions, membership management, Profile, Team, Classroom, Remix, provenance, ownership transfer, and hard delete remain outside this sprint.
